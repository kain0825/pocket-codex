# 维护和发布

推送前：

1. 运行电脑端回归与监控假执行器检查。
2. 构建固件，记录工具链、配置和应用哈希；单独说明本次有无实机验收。
3. `git add` 后运行 `python scripts/audit_public.py` 检查暂存区。不要强制添加忽略文件。
4. 核对README、验证记录和已知问题，防止把历史原系统的验收写成新版本全部通过。
5. 使用维护者自己的GitHub登录推送；仓库不提供任何账号访问凭据。

首版建议使用 `v0.1.0-preview` 标记源码预览。GitHub可以自动生成源码包；需要本地配对的二进制不要作为通用固件发布。

给视频观众的入口应使用仓库主地址或README，不使用个人聊天链接、配对链接或带token的本机预览地址。
